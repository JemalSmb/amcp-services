# AMCP Platform Services

Domain microservices for the AMCP platform. Split out from
`amcp-platform-core` (which only holds infra config and domain manifests)
into its own repo so services can be built, versioned, and deployed
independently of the core platform config.

Each service consumes domain events over NATS, scores them against a model
served by the [inference service](../../amcp-ai-engine/ai/inference), and
publishes an alert event back onto NATS. See `shared/base_service.py` for
the generic implementation of that flow and
`services/cybersecurity/threat-detection/` for a worked example.

## Implemented (working end-to-end)

| Service | Domain | Model | Input subject | Output subject |
|---|---|---|---|---|
| `threat-detection` | cybersecurity | `anomaly_detection` | `cyber.events.threats` | `cyber.alerts.threats` |
| `phishing-detector` | cybersecurity | `phishing_detection` | `cyber.events.phishing` | `cyber.alerts.phishing` |
| `fraud-detector` | finance | `finance_fraud_anomaly` | `fin.transactions.incoming` | `fin.alerts.fraud` |
| `process-anomaly-detector` | manufacturing | `manufacturing_process_anomaly` | `mfg.sensors.process` | `mfg.alerts.process` |

These are the only four models the inference service currently has
registered — see `amcp-ai-engine/ai/inference/registry.py`.

## Everything else

The remaining ~28 services named in `amcp-platform-core/domains/*/domain.yaml`
(fuser-correlator, iot-anomaly-detector, aml-monitor, equipment-health-monitor,
etc.) are structure-only stubs generated by `scripts/generate_stubs.py`:
a `/health` endpoint and a README explaining what training + wiring work
is needed to turn each into a real service. They are not started by
`docker-compose.services.yaml`.

## Running a service locally

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt

# terminal 1: NATS
docker run --rm -p 4222:4222 nats:2.10-alpine

# terminal 2: inference service (see amcp-ai-engine/ai/inference/README.md)
cd ../../amcp-ai-engine/ai/inference && uvicorn serve:app --port 8000

# terminal 3: a domain service
PYTHONPATH=. NATS_URL=nats://127.0.0.1:4222 INFERENCE_URL=http://127.0.0.1:8000 \
  .venv/bin/python services/cybersecurity/threat-detection/service.py
```

Every service also exposes `GET /health` and `POST /trigger` (a
`{"features": {...}}` body) so the full validate -> infer -> publish flow
can be exercised over plain HTTP without a NATS broker running.

## Running with Docker Compose

Requires `amcp-platform-core`'s core infra network to exist first:

```bash
cd ../../amcp-platform-core && docker-compose -f docker-compose.core.yaml up -d
cd ../amcp-ai-engine/ai/inference && docker-compose -f docker-compose.inference.yaml up -d
cd ../../../amcp-services/amcp-platform-services && docker-compose -f docker-compose.services.yaml up -d
```

## Event contract

`shared/events.py` defines `DomainEvent`, a local copy of the shape
defined in `amcp-platform-core/domains/_base/service_interface.py`. Kept
as a plain dataclass here (no dependency on amcp-platform-core at runtime)
so this repo stays deployable on its own.
